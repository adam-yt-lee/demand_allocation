# 戰情分析：需求齊套分配系統

> **適用對象：** 供應鏈主管、業務主管、生產計劃負責人
> **使用場景：** 庫存不足時，決定「優先滿足哪些訂單」以最大化出貨效益

---

## 一、解決什麼問題？

當手上的料不夠滿足所有訂單，傳統做法是靠人工經驗排序，費時且容易遺漏。

**本系統解決三個核心決策問題：**

| 問題 | 系統提供的答案 |
|------|--------------|
| 哪些訂單本月可以完整出貨？ | 即時顯示 ✅ 可滿足 / ❌ 缺料 的訂單清單 |
| 缺什麼料？缺多少？ | 逐筆顯示各料號的供給缺口與數量 |
| 如何排序才能讓最多訂單出得去？ | 一鍵自動最佳化，系統算出最優排序 |

---

## 二、核心業務邏輯

### 扣料原則

系統依照**優先順序**逐筆處理需求，採用「全套才扣」規則：

- 一筆需求的**所有料件全部到位** → 標記 ✅，從庫存扣除
- 任何一項料件不足 → 標記 ❌，**庫存不扣**（保留給下一筆）

這確保了資源不會被「不完整的訂單」提前佔用。

### 供給計算邏輯

| 供給類型 | 計算方式 |
|---------|---------|
| 現有庫存（STOCK） | 所有月份皆可使用 |
| 在途進料 | 僅納入到貨日 ≤ 需求月份的進料 |

### 優先順序設定

拖曳調整訂單順序，系統即時重新計算所有結果。亦可凍結特定訂單（不參與分配），模擬不同情境。

---

## 三、自動最佳化

點擊「**⚡ 自動最佳化**」，系統以數學規劃（Branch-and-Bound 整數規劃）自動找出最優排序：

- **目標：** 最大化可完整滿足的訂單數量
- **限制：** 各月供給量、料件替代選項
- **結果：** 顯示「X / Y 筆需求可滿足」，並自動調整排序

> 若資料量大、計算超過 10 秒，系統會顯示「非最優解」提示，仍為合理的優化結果。

---

## 四、使用流程

```
1. 準備 Excel 檔案（含 Demand、Supply 兩個工作表）
         ↓
2. 上傳檔案 → 系統自動驗證並載入
         ↓
3. 檢視左側訂單卡片，確認 ✅/❌ 狀態
         ↓
4. 按需拖曳調整優先順序，或點擊「⚡ 自動最佳化」
         ↓
5. 右側查看供給缺口彙總表，確認剩餘庫存
         ↓
6. 下載結果，做為排程依據或主管簡報
```

## 五、Excel 資料格式

### Demand 工作表（需求）

| 欄位 | 說明 | 範例 |
|------|------|------|
| Demand | 訂單/需求名稱 | `ORDER-A001` |
| Group | 料件群組 | `PCB` |
| Name | 料件名稱/規格 | `PCB-V2` |
| Qty | 需求數量 | `100` |
| Month | 需求月份（YYMM） | `2504`（2025年4月） |

### Supply 工作表（供給）

| 欄位 | 說明 | 範例 |
|------|------|------|
| Group | 料件群組 | `PCB` |
| Name | 料件名稱/規格 | `PCB-V2` |
| Qty | 數量 | `500` |
| Month | 到貨月份或 `STOCK`（現有庫存） | `2504` 或 `STOCK` |

> 點擊畫面上的「下載範本」按鈕可取得標準格式範本。

## 六、畫面說明

### 左側：訂單需求卡片

- 每張卡片顯示訂單名稱、需求月份、狀態徽章
- 展開後可查看各料件的需求量、可用量、缺口
- 若某料件有多個供應來源，可選擇使用哪個料號

### 右側：供給缺口彙總

- 按料件群組整理庫存現況
- 顯示庫存量、在途量、已承諾量、剩餘量
- 滑鼠懸停可查看哪些訂單使用該料件

---

## 七、常見情境應用

**情境 A：月底出貨優先排序**
> 將本月到期訂單置頂，執行自動最佳化，快速得出最多訂單可出貨的排序方案。

**情境 B：VIP 客戶保護**
> 將 VIP 訂單勾選並鎖定優先（拖曳至最頂），其他訂單再執行最佳化。

**情境 C：模擬進料延遲影響**
> 調整 Supply 表的到貨月份，重新上傳，即可看到延遲對各訂單的衝擊。

**情境 D：替代料評估**
> 在 Supply 表中加入替代料（相同 Group、不同 Name），系統自動納入最佳化計算。

---

## 八、快速上手

1. 用瀏覽器開啟 `index.html`（無需安裝、無需網路）
2. 點擊「下載範本」，依格式填入貴司資料
3. 上傳 Excel，開始分析

**系統需求：** 現代瀏覽器（Chrome / Edge / Firefox）即可，無需後端伺服器。

## 附錄：術語對照

| 系統用語 | 業務含義 |
|---------|---------|
| ✅ OK | 該訂單料件齊套，可完整出貨 |
| ❌ 缺料 | 至少一項料件不足，無法出貨 |
| ⊘ 凍結 | 已停用，不參與本次分配計算 |
| 扣料 | 訂單確認可出後，從庫存中扣除對應數量 |
| 齊套 | 一筆訂單所需的所有料件均備齊 |
| 供給缺口 | 特定料件的需求量超出可用量的差額 |
